MCAS-ICT — STAGED PROMPTS FOR OPENCODE
==========================================
Run these ONE AT A TIME. Review the diff after each before moving to the
next. Do not paste all of these in one message — opencode will try to do
too much at once and you lose the ability to catch mistakes early.

---------------------------------------------------------------
PROMPT 1 — Project scaffold
---------------------------------------------------------------
Set up a monorepo with two folders: `frontend/` (React + Vite + TypeScript
+ Tailwind CSS, with the Vite PWA plugin configured) and `backend/`
(Node.js + Express + TypeScript). Use the folder structure exactly as
described in 01_project_overview.txt. Install and configure: for frontend
— react-router-dom, @supabase/supabase-js, dexie, react-hook-form, zod,
lucide-react, recharts, leaflet + react-leaflet, html5-qrcode, jspdf. For
backend — @supabase/supabase-js, zod, helmet, cors, express-rate-limit,
node-cron, dotenv. Set up ESLint + Prettier for both. Do not write any
business logic or UI yet — just working scaffolds with a placeholder
homepage and a health-check API route (GET /api/health).

---------------------------------------------------------------
PROMPT 2 — Database schema + Supabase setup
---------------------------------------------------------------
Using 02_database_schema.txt exactly as written, create the SQL migration
file(s) for Supabase (enums, tables, indexes, RLS policies). Put them in
backend/sql/migrations/. Also generate the matching TypeScript types in
backend/src/types/db.ts and a shared copy in frontend/src/types/db.ts.
Do not modify the schema — flag anything you think is wrong instead of
silently changing it.

---------------------------------------------------------------
PROMPT 3 — Auth middleware + role guards
---------------------------------------------------------------
Implement backend/src/middleware/authenticate.ts (verifies Supabase JWT
from Authorization header, attaches req.user with id/role/department_id
looked up from the profiles table) and requireRole(...roles) middleware.
Add GET /api/me. On the frontend, set up the Supabase client
(frontend/src/lib/supabase.ts), a login page, and an auth context/hook
that exposes current user + role. Follow 04_frontend_ui_design_spec.txt
for the login page styling — light mode, no gradients, council-teal
accent only on the primary button.

---------------------------------------------------------------
PROMPT 4 — Assets CRUD (backend + frontend)
---------------------------------------------------------------
Implement the Assets routes from 03_backend_api_spec.txt (GET list with
filters, GET by id, POST, PATCH, DELETE) with Zod validation and role
guards. On the frontend, build the Assets list page (DataTable component,
filter bar) and Asset detail page for supervisor/admin, following
04_frontend_ui_design_spec.txt component conventions exactly (StatusBadge,
Card used sparingly, no shadow-lg). Include an Add/Edit Asset form using
React Hook Form + Zod matching the backend schema.

---------------------------------------------------------------
PROMPT 5 — Inspection flow (online-only first)
---------------------------------------------------------------
Build the technician-facing inspection flow: mobile-first multi-step form
(asset lookup via QR scan using html5-qrcode OR manual asset_tag entry ->
condition status -> photo upload to Supabase Storage via signed URL ->
GPS capture via Geolocation API -> submit). Implement POST /api/inspections
on the backend including the service that recalculates the asset's
current_status and writes an audit_log row. No offline handling yet —
this version assumes network is available. Follow the technician mobile
layout spec (bottom nav, big tap targets, linear steps not one long form).

---------------------------------------------------------------
PROMPT 6 — Offline queue + sync
---------------------------------------------------------------
Add Dexie.js local database mirroring the inspection payload shape.
When the inspection form is submitted while offline (or a submit fails),
queue it locally with a generated client_uuid and sync_status: 'pending'
instead of failing. Implement POST /api/inspections/sync as a batch
upsert endpoint keyed on client_uuid (idempotent). Add a background sync
trigger (on reconnect + periodic retry) and a small UI indicator showing
pending/synced count. Cap batch size server-side at 50 per request.

---------------------------------------------------------------
PROMPT 7 — Supervisor dashboard + maintenance workflow
---------------------------------------------------------------
Build the supervisor dashboard: status breakdown chart (Recharts, using
the muted status colors from the design spec, not default chart colors),
assets map view (Leaflet + OpenStreetMap markers colored by status), and
a maintenance requests list with approve/assign/status-update actions.
Implement the maintenance_requests endpoints and the auto-creation
service that opens a request when an inspection status is 'poor' or
'disposal'.

---------------------------------------------------------------
PROMPT 8 — Admin module + reports
---------------------------------------------------------------
Build admin-only pages: user management (invite/edit/deactivate,
assign role + department), disposals workflow, and reports (summary
counts, depreciation table, replacement-due list). Generate PDF export
client-side with jsPDF (not backend-generated) matching the report
layout in a simple, print-appropriate style — no color backgrounds,
readable in black and white.

---------------------------------------------------------------
PROMPT 9 — PWA polish + deploy prep
---------------------------------------------------------------
Finalize the Vite PWA config (manifest, icons, offline app-shell caching
via Workbox), verify the app installs correctly on Android/desktop, add
loading/empty/error states to any screen missing them, and prepare
environment variable templates (.env.example) for both frontend and
backend ready for Vercel (frontend) and Render (backend) deployment.
