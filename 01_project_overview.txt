MCAS-ICT — PROJECT OVERVIEW & ARCHITECTURE
============================================

PROJECT
-------
ICT Asset Management System for Mutare City Council.
Web + PWA app replacing manual/Excel asset tracking with a centralized
system for ICT Technicians, Supervisors, and Admins.

TECH STACK
----------
Frontend:      React + Vite + TypeScript
UI:            Tailwind CSS + Lucide React icons
Backend:       Node.js + Express.js + TypeScript
Database:      Supabase PostgreSQL
Auth:          Supabase Auth (JWT, role-based)
File Storage:  Supabase Storage (asset photos)
PWA:           Vite PWA Plugin + Service Worker
Offline Sync:  IndexedDB via Dexie.js (write queue pattern)
GPS:           Browser Geolocation API
Maps:          Leaflet + OpenStreetMap
QR/Barcode:    html5-qrcode
Charts:        Recharts
Forms:         React Hook Form + Zod
Reports:       jsPDF
Deployment:    Vercel (frontend) + Render (backend)
VCS:           Git + GitHub

USER ROLES
----------
1. Technician — inspects assets, submits condition reports, logs faults/repairs
2. Supervisor — views dashboard, approves maintenance, assigns technicians
3. Admin — manages users, generates reports, full CRUD access

DEVELOPMENT PRINCIPLES
------------------------
- Backend owns all business logic (depreciation calc, status flagging,
  scheduling). Frontend never re-implements these rules.
- Every write endpoint validated with Zod on both frontend (pre-submit)
  and backend (source of truth).
- Role checks enforced server-side via middleware, never trusted from
  frontend state alone.
- Offline queue (Dexie) mirrors the Inspections table shape; sync
  reconciliation happens server-side, last-write-wins per record.
- No feature ships without: loading state, empty state, error state.
